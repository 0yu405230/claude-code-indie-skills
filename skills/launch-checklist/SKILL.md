# launch-checklist — ローンチ前チェックリスト

> 個人開発収益化Skill集(非公式・Claude Code対応)収録 / v0.1.0
> パイプライン位置: 仕様化 → 実装 → 監査 → 販売文 → **[ローンチ確認]**

公開ボタンを押す前の最終点検を行う。目的は「公開を止めること」ではなく、**直せる事故を公開前に直すこと**。

## 発動すべき場面
- Webサービス/アプリを公開・デプロイする直前
- 有料note・Zenn本・BOOTH/Tips商品の販売を開始する直前
- 無料公開でも、メールアドレス収集や外部決済リンクを含むページを出すとき
- 「もう出していい?」「リリース前に見て」と言われたとき

**運用ルール:** チェックなしの公開・販売開始を黙認しない。公開の話題が出たら本Skillの実行を提案する。

## 使ってはいけない場面
- コードの詳細なセキュリティ監査(それは project-audit の仕事。本Skillは公開判断の最終点検)
- 法的な適法性の最終判断(チェック項目の指摘までが範囲。判断は公式情報・専門家へ)
- 公開後の障害対応(本Skillは事前点検専用)

## 実行手順
1. まず「何を・どこで・いくらで・いつ」公開するのかを特定する(不明なら1回だけ質問)
2. 公開形態を判定する: (A) Webサービス / (B) プラットフォーム販売(note/Zenn/BOOTH/Tips) / (C) 両方
3. 該当するカテゴリのチェック項目を1つずつ検査し、**OK / NG / 不明(ユーザー確認要)** の3値で判定する。根拠なしにOKを付けない。確認できないものは必ず「不明」とする
4. NGと不明を「公開ブロッカー(Must)」と「公開後でも可(Should)」に仕分ける
5. 総合判定を出す: 「ブロッカー0件 → 公開可能と判断できる状態」/「ブロッカーあり → 解消手順を提示」。最終判断はユーザーが行うことを明記する
6. ブロッカーの解消手順を優先度順に列挙する

## チェック項目(本体)
### 共通(A/B両方)
- [ ] 誇大表現: 収益断定(「稼げる」「月◯万円」)、根拠のない最上級(「業界No.1」)、実績の捏造・誇張がないか
- [ ] 価格と提供物の一致: 販売ページに書いた提供物が実際に全て含まれるか
- [ ] 返金・キャンセル方針: 明記されているか(プラットフォームの場合は規約準拠を確認)
- [ ] 問い合わせ導線: 連絡手段が最低1つ機能しているか
- [ ] 非公式表記: 他社製品名を使う場合、公式と誤認されない表記か
- [ ] 他者コンテンツ: 画像・文章・コードに権利不明なものが混入していないか

### A: Webサービス
- [ ] 特商法表記・プライバシーポリシー・利用規約のページが存在し、実態と一致しているか(有料なら特商法は必須)
- [ ] 環境変数: APIキー・シークレットがリポジトリやクライアントに露出していないか
- [ ] 認証と権限: 他人のデータが見えないことを2アカウントで確認したか(Supabase等はRLS有効か)
- [ ] 決済: テスト決済→本番決済の切替、Webhook動作、二重課金時の対処を確認したか
- [ ] コスト暴走対策: AI API呼び出しにレート制限/利用上限があるか
- [ ] エラー時の見た目: 主要操作の失敗時にユーザー向けメッセージが出るか
- [ ] 計測: 最低限のアクセス/登録/課金の数が後から分かるか

### B: プラットフォーム販売(note/Zenn/BOOTH/Tips)
- [ ] 当該プラットフォームの最新規約・ガイドラインを確認したか(情報商材的表現の制限、禁止商材)
- [ ] 特商法まわりの表記方法がプラットフォームの方式に沿っているか(※方式は各社で異なり変更されうる。必ず当日最新を確認)
- [ ] 無料部分だけで「何が買えるのか」が誤解なく分かるか
- [ ] 目次・提供物一覧・対象者・対象外の人 が明記されているか
- [ ] ファイル配布がある場合、ダウンロード方法と更新方針を書いたか

## 入力テンプレート
```
【公開するもの】(サービス名/記事名/商品名)
【形態】(Webサービス / note / Zenn / BOOTH / Tips / その他)
【価格】(無料 / ¥◯◯)
【公開予定日時】
【URL/本文/リポジトリ】(見せられる範囲で)
```

## 出力フォーマット
```
# ローンチ前チェック結果: {対象名}
## 総合判定: {公開可能と判断できる状態 / ブロッカー◯件あり}(最終判断はご自身で)
## 判定表
| # | 項目 | 判定 | 根拠・確認方法 |
|---|---|---|---|
## 公開ブロッカー(Must)
1. {内容} → 解消手順: {手順}
## 公開後でも可(Should)
## 未確認(ユーザーにしか確認できない項目)
## 免責
```

## 品質チェックリスト
- [ ] 全項目に3値判定(OK/NG/不明)が付いているか。根拠なしOKがないか
- [ ] ブロッカーに具体的な解消手順が付いているか
- [ ] 「最終判断はユーザー」の明記があるか
- [ ] プラットフォーム規約は「当日最新を確認」と促しているか

## 禁止事項
- 確認していない項目を「OK」と判定すること(最重要)
- 「法的に問題ありません」等の適法性の断定
- チェックを省略して「大丈夫です、公開しましょう!」と即答すること
- ユーザーが急いでいても、Must項目の検査を飛ばすこと

## 免責・注意書き
本チェックは公開前の見落とし防止を目的とした補助であり、適法性・安全性を保証するものではありません。法令・各プラットフォーム規約は変更されるため、公開当日に最新の一次情報を確認してください。

## 悪い出力例(こうしない)
> 全部確認しました!問題ありません。自信を持って公開しましょう🎉

NG理由: 根拠なし全OK/判定表なし/未確認項目の隠蔽/保証表現。

## 良い出力例(抜粋)
> **総合判定: ブロッカー2件あり(解消後に公開推奨。最終判断はご自身で)**
> | # | 項目 | 判定 | 根拠・確認方法 |
> |---|---|---|---|
> | A-2 | APIキー露出 | NG | `lib/ai.ts` にキーが直書き。環境変数へ移し、キーを再発行する |
> | B-2 | 特商法表記 | 不明 | 販売プラットフォームの現行方式を本日確認要 |
> | 共-1 | 誇大表現 | OK | 本文走査済み。収益断定・最上級表現なし |

## コールドスタートテスト
**サンプル入力:**
```
【公開するもの】Claude Code向けSkill集の有料note記事
【形態】note
【価格】¥980
【公開予定日時】明日20:00
【URL/本文/リポジトリ】(本文ドラフトを添付)
```
**合格基準(8割品質の定義):**
- B系+共通の項目が判定表形式で出力され、全項目に3値判定と根拠がある
- 誇大表現チェックと特商法まわりの「当日最新確認」の指摘が含まれる
- ブロッカーと解消手順が分離されている/「最終判断はユーザー」と免責がある
- 根拠のない「全部OK」判定が存在しない
